Experiment E2 · E3 · E4 — "Sextant" did not converge

Sextant Forty rounds of adversarial review across two targets, with a mechanical self-induction oracle, seeded-defect recall, and unseeded controls attached. The successor run to Ouroboros, measured against it on every axis it published.

Ouroboros converged in 21 rounds and its own analysis said the stopping rule had decoupled from value eight rounds early. Sextant rebuilt the loop around external oracles and ran it twice as far. Self-induction halved. Convergence never fired. Cost per finding rose faster than it did in Ouroboros, and over half the blocking findings still pointed at code the loop itself had written.

01  What was run

Sextant reviewed M3 — the constraints UI, fuzzy search and path finder features, plus the core additions underneath them — on two targets in parallel, lib/src (the zero-dependency graph core) and app/src (the React front-end). Ouroboros reviewed one target, app/src, on M2.

Five lenses ran each round instead of four: correctness, security, SOLID, maintainability, and a new interaction/accessibility lens. Lenses were spread across models rather than all running the same one. Every round ran a lint gate first, clustered findings by theme, fixed each confirmed non-deferral finding under a subtractive fix skill, and ratcheted an invariant — not a case — into the suite.

02  What worked

Five changes carried measurable weight. Each is stated with the number that supports it.

1. Self-induction halved, and the oracle has no model in it

A finding is self-induced when git blame puts the line it cites in an earlier fix commit of the same loop, blamed against the tree that round's critics actually saw. No agent judges anything.

The pre-registered E2 criterion — the injected-defect rate falls by at least half against E1's re-derived blame-oracle rate — is met on the aggregate. Ouroboros's finding location was 3.37× enriched for its own code; Sextant's is 1.40×.

2. The interaction lens was the most productive one, on the smallest model

Lens rotation was the cheapest change in the design and it returned the most. The new interaction lens filed the fewest findings and the highest share of blocking ones.

In Ouroboros the equivalent split was correctness 17, SOLID 24, security 14, maintainability 37 — with SOLID the second-largest producer. Here it produced 47 findings and zero blocking ones across 40 rounds, and 30 of them were deferrals.

3. External oracles closed themes that critic attention could not

Every blocking finding in the last five rounds of each target was closed by adding an oracle rather than by adding scrutiny: a bridge-exact connectivity repair written in the Python reference first and validated cross-language; a work budget that counts what it spends instead of predicting it; a source-reading guard that fails when three hard-constraint enforcement sites stop covering the same kinds; a CSS guard that fails when any rule hides a live region.

The lint gate is the sharpest single datum. Replaying today's rule set over Ouroboros's own history, one violation site survived all 21 of its review rounds — a mechanical check catches what twenty-one rounds of adversarial reading did not. (Lower bound: only the oxlint rules can be replayed at those refs; the custom checks and dead-export analysis cannot.)

4. Deferrals stopped the loop building scaffolding for unbuilt features

Ouroboros spent 8 findings over 6 rounds hardening an extension seam for a layout mode that was never built — every one a suggestion, none blocking. Sextant added a deferral severity with a mechanical test (does a caller exist in the current tree?) and logged 56 of them, none of which gated convergence and none of which became code.

5. Agent-level resumability turned a halt from a lost round into a lost third

Three session-limit halts hit the run. The first killed three lenses mid-round and the round was recorded contaminated — it is still flagged by the round-log script on every run. The second killed everything and cost a full re-run. The third was replayed from the runner's per-agent journal: only the killed lenses re-ran, at roughly a third of a round. The unit of retry has to be the agent, not the round.

The two smaller levers were real but modest: theme clustering collapsed 276 raw findings into 219 themes (20.7%), and saturation gating skipped 16 critic-rounds, worth about 1.57 M tokens — 7.2% of the run.

03  What did not work

Stated at the same resolution as the successes, because a result that can only succeed is not a measurement.

1. Convergence never fired, in either target, in twenty rounds each

The rule is a round with zero confirmed non-deferral findings, then one confirming round. Neither target ever produced the first. The best rounds were lib 18 (one suggestion) and app 17 (one blocking). Both targets then produced fresh blocking findings at rounds 17 and 20 — the false-summit shape Ouroboros described, observed twice more.

Blocking findings per round — lib/src (left), app/src (right)

2. Cost per finding rose faster than it did in Ouroboros

Ouroboros's headline was 47 K → 143 K tokens per confirmed finding, a 3.04× rise across its two regimes. Sextant, measured in five-round windows against gating findings (blocking + suggestion):

Per blocking finding the last window cost 541 K on lib and 1.08 M on app — a 7.9× rise from the first window, against Ouroboros's 3.04×. Reforming the loop did not flatten the curve; on this axis it steepened it.

3. Over half the blocking findings were still the loop's own work

The aggregate improvement is carried by the cheap tier. Split by severity, the picture inverts:

By window, self-induction runs 14% / 30% / 31% / 22% on lib and 10% / 31% / 28% / 24% on app. It rises after the first five rounds and then plateaus. It does not decay. A loop whose blocking findings are half its own output does not have a descending residual; it has a fixed point above zero.

4. The gate that was designed was never the gate that ran

The design says a finding with no statable machine-checkable invariant is filed caseOnly and does not gate convergence — the mechanism intended to stop the preference tail from blocking forever. Critics set the flag on 23 of 304 findings (10 of them in the first five rounds, 2 in the last five). In practice every suggestion gated. The reform most directly aimed at Ouroboros's stated cause of non-convergence was left to agent self-declaration and therefore never operated.

5. Precision was measured, and it is not good

Four unseeded clean worktrees drew 20 findings, 14 of them gating. On code with no planted defect, the ensemble still files roughly three-and-a-half gating findings per surface. Ouroboros had no controls at all, so this is new information rather than a regression — but it means the loop's output cannot be read as a defect list without confirmation.

6. The seeded-recall corpus never reached its pre-registered size

The pre-registration specified roughly 24 seeds in two strata with a 12-seed prose subset. What was actually scored was 5 seeds, all from the mutation stratum: recall 0.80 (4 of 5), one blind spot (a dropped guard clause in the canvas neighbourhood derivation), and a leave-one-out showing that removing the correctness lens drops recall to 0.40 while removing SOLID or maintainability costs nothing. At n=5 those are existence claims and nothing more. The real-reverted-defect stratum, which was the arm designed to carry E4's zero-loss test, was never built.

7. It tripled the comment-to-code ratio, and no instrument saw it

Found by the repository's owner in one sentence, after forty rounds and five lenses had not looked at it. Measured across lib/src + app/src:

lib/src/core/budgets.ts reached 6.4 comment lines per line of code — 313 lines of prose around 49 lines of arithmetic — and the largest single comment block in the tree was 41 lines.

The mechanism is the loop, not a taste for explaining. Each round embedded the case against a rejected alternative in the source so the next round would not re-propose it. That is writing to critics: the review ends at merge, and the comment is read for years by people who were never in the argument. It is E1's self-reference surfacing in an artifact nobody thought to measure — invisible to every instrument either experiment built, because it is not a finding, not a defect, not a token cost, and no lens files it.

Two facts make this the most uncomfortable entry on the page. It is label-free — git answers it, no agent judges anything — so it could have been tracked from round one for nothing. And it was found by a human reading a diff, in one sentence, after 21.7 M tokens of adversarial review had not.

8. The measurement apparatus needed reviewing too

Two defects in the self-induction oracle were found only when it was pointed at the full 40-round dataset. It discovered fix commits by matching one commit-subject shape; the run's own subject style drifted after round 5, so 34 of 40 fix commits went unrecognised and every finding from round 6 on fell into unknown — the instrument reported 23.3% off six of forty rounds and looked conservative doing it. Separately it took the chance base rate once on the final tree, where fix-authored code is at its maximum, and compared it against a run-averaged observed rate, producing a lift of 0.73× — the loop apparently avoiding its own code. Both are corrected here; both were silent.

The honest reading. Sextant is a better-instrumented loop that found more real defects and manufactured proportionally less of its own work — and it is further from a stopping rule than the run it was designed to improve on. Ouroboros converged and its own analysis said the convergence was hollow. Sextant did not converge, and it is not clear that its failure to is worse evidence than Ouroboros's success was.

05  In hindsight

Four things that were knowably wrong at the time, not with the benefit of the result.

  • The rationale for a fix should have gone in the commit message, never in a source comment. The repository already said so — lib/CLAUDE.md's quality bar reads "code is self-documenting; add a short comment only when the why is non-obvious" — and forty rounds went past it, tripling the ratio. A reviewer's job is to convince; the author's is to adjudicate and record the decision where it belongs. Writing the argument into the code was never the right medium and did not need a result to establish that.
  • The self-induction oracle should have asserted its own coverage from round one. It discovered fix commits by regex and never checked that every round in the dataset mapped to one. The check is four lines and it now prints any unmapped round. A silent unknown bucket reads as caution and is blindness.
  • The base rate should have been computed per round from the start. Comparing a run-averaged observed rate to an end-of-run chance rate is a denominator mismatch, not a subtle statistical point — fix-authored code accumulates monotonically and the final tree is the largest that share ever is.
  • caseOnly should have been decided mechanically, not by asking critics to self-declare it. The design named the flag as the mechanism that would stop the preference tail gating convergence, then delegated it to the same judgement the experiment exists to remove. Ten uses in the first five rounds and two in the last five is what that delegation bought.
  • The saturation state channel should have been wired before round one. The lever was designed, committed, and did not fire for the first several rounds because the caller never passed the state in — recorded in the run's own history as a fix, which means several rounds of the A3 measurement describe a mechanism that was not running.

06  Open questions

Unresolved by this data, stated so a later run can attack them rather than rediscover them.

  • Does this loop have a fixed point above zero, or an unbounded suggestion space? Forty rounds is consistent with both. They are distinguishable only by a run that reviews the same tree repeatedly without fixing anything — which no round of either experiment did.
  • Is the interaction lens's 60% blocking rate a property of the lens or of the model? The new lens and the new model tier arrived in the same change. The confound is total and was not designed out.
  • Is SOLID worth running? Zero blocking findings in 40 rounds and zero recall cost in leave-one-out say no. Thirty-two themes no other lens raised say the question is not settled by those two numbers alone.
  • What is inside the 92-finding unknown bucket? Blame-based attribution is documented as weakest on non-functional findings, and three of five lenses file mostly those. The self-induction figure is measured over 212 classifiable findings, not 304.
  • Does an invariant ratchet generalise better than a case ratchet? Ouroboros doubled its suite (68 → 136); Sextant grew it 27% (448 → 568) while requiring every guard to be a property. The claim that fewer, broader tests catch more is untested — neither run measured a suite against defects it had not already seen.
  • What is the effective false-positive rate on the real target? The controls measure it on clean trees. On a tree with real defects, nothing distinguishes "filed and not acted on" from "filed, real, and deferred".
  • Would two consecutive clean rounds ever fire? Never observed, so the second confirming round — inherited from Ouroboros, where it did supply robustness — is untested here.
  • What else did the method inflate in a dimension nothing measures? The comment-density result is one instance of a class, and it was found by a human rather than by any of the five lenses or six metric scripts. Abstraction count, indirection depth, test-to-assertion ratio and public API surface are all label-free, all plausibly inflated by the same pressure, and none of them were recorded. "What did the loop make worse where it was not looking" is a question neither experiment asked.

07  Method & provenance

Deterministic — reproducible from the repository

  • Round records: data/rounds/{lib,app}-round-NN.json, one per round, saved verbatim from the runner plus a token block. Forty files.
  • Normalised dataset: data/findings_full.json, perRound.json, rounds.json, produced by scripts/review-metrics/round-log.mjs.
  • Self-induction: scripts/review-metrics/self-induction.mjs — git blame against each round's reviewed tree, four blame configurations, per-round base rate, explicit unknown bucket.
  • Lever savings: scripts/review-metrics/lever-a-savings.mjs — lint replay over E1's refs in temporary worktrees, theme collapse per round, skipped critic-rounds × measured mean agent cost.
  • Ouroboros comparison figures: data/e1-self-induction.json, data/e1-fix-churn.json, computed by the same oracles run backwards over claude/m2-xapjhu.
  • Test counts: both suites executed at 544940f (last M3 feature commit, before round 1) and at the final commit.
  • Comment-to-code: counted over lib/src + app/src at three refs (24b5dd6 M2 baseline, 544940f pre-loop, final commit), by the same line classifier at each. Block comments count every line; a trailing comment on a code line counts as code, so the figures are a lower bound.

Interpretive — judgement, labelled as such

  • Severity is assigned by the filing critic. "Blocking" is its claim, verified by a second agent, not by an oracle.
  • The five-round windows are a presentation choice. They are not a claimed regime boundary; Ouroboros's two-regime split was located by four independent analyses and this one is not.
  • "Closed by an oracle rather than by scrutiny" in §2.3 is a reading of the last ten rounds' fix commits, not a computed statistic.
  • Blame attribution is an instrument with a published error bar (best measured F1 ≈ 0.7), not ground truth. It is reported with sensitivity and an unknown bucket for that reason.

Known contamination

  • lib-round-02 lost three lenses to a session halt and is recorded with them dead. round-log.mjs warns about it on every run; it is not excluded, because excluding a round after seeing its contents is the selection the pre-registration forbids.
  • app-round-07 shows 31 K tokens against a run average near 600 K — a resumed round replayed almost entirely from the agent journal. Its findings are real; its token figure is not comparable and is left in rather than adjusted.
